The admin API of the WCS equipment emulator, test infrastructure that stands in
for ISA-95 levels 1 and 0: AMR robots speaking VDA 5050 v3 and an AS/RS PLC
speaking telegram protocol v1, both over MQTT. This REST API only inspects the
simulated world, injects faults and seeds stock; it never carries robot or PLC
traffic and never calls a sibling context.

Fault injection is idempotent by construction: a fault is switched on or off
with `active`, so repeating a request converges to the same state.

Every POST accepts the fleet `Idempotency-Key` header (ADR 0006). It is
OPTIONAL here, unlike the rest of the fleet: without it a POST simply runs;
with it a retry under the same key is answered from the store by the replay
class of the first answer. Keys live in process memory for 24 hours and are
lost when the emulator restarts (the emulator has no database, ADR 0001).

`GET /robots` pages with `limit` and an opaque keyset `cursor` and answers
`{items, nextCursor}`.

Errors are RFC 7807 problem documents served as `application/problem+json`;
`code` is the stable problem slug. There is no authentication layer (fleet
decision 2026-09-11).
